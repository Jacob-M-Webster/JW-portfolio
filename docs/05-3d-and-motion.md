# 05. 3D and motion

The point-cloud scene is the memorable thing on the page, so it gets a precise spec. Everything here has a budget and a fallback.

---

## 1. Concept

A framed **sensor viewport** shows a point cloud, rendered the way a LiDAR viewer draws returns: each dot is colored by height (ground blue, body teal, top yellow), and a rotating beam makes points brighten as it passes and fade behind it. Range rings on the ground echo the sensor's polar grid.

Three scene states:
- **Scatter**: loose, quiet points drifting slowly (the ambient state).
- **Car**: a generic autonomous-vehicle silhouette sampled from a purchased model (see section 2).
- **Quadruped**: a generic four-legged robot generated from primitives. It is not a replica of any real product.

The scene mirrors where the reader is on the page: car in the hero, quadruped while the Spot row is in focus, car again for WayFinder, scatter for Baton and onward.

**Honesty rule:** the viewport is an illustration. The caption says so. It must never imply the point cloud is real data from Jake's sensors. The only live number allowed is the actual count of points being drawn.

## 2. Asset pipeline

### 2.1 Rules (licensing and repo hygiene)

- Jake purchased a royalty-free license for the car model. Raw files live in `/assets-private/` (gitignored). They never enter `public/`, `src/`, the build output, or git history.
- Only derived point-cloud binaries ship. The pipeline is run by hand, offline; it is never part of the production build.
- Derived output is committed (small, deterministic, reviewable): `public/models/scene-points.bin` and `public/models/scene-points.json`.
- `scripts/check-assets.*` enforces all of the above (section 9).

### 2.2 Inputs

- Car source: one of the purchased OBJ/FBX/glTF files (decision D10 in `README.md`). Stage 3 renders a quick sampled preview of each candidate and picks the better silhouette.
- Quadruped: generated from parametric primitives (section 2.5). No third-party model.

### 2.3 Car sampling (`scripts/mesh_to_points.py`)

1. **Inspect and report.** Load the mesh (trimesh or equivalent). Print every group or object with name, face count, bounding box. Save the report to `docs/asset-report.md` (names and numbers only; no mesh data).
2. **Exclude non-body geometry.** Remove ground or shadow planes (for example the ambient-occlusion ground texture), cameras, lights, and any group Stage 3 identifies as interior. The exclusion list is written to the report and kept in the script.
3. **Visibility filter (if interior points remain).** Cast rays from about 64 camera positions on a sphere around the model; keep only sample points visible from at least one exterior position. Record kept versus dropped.
4. **Sample.** Area-weighted surface sampling, `N = 30,000` points, fixed random seed.
5. **Normalize.** Center on X and Z, put the lowest point at `y = 0`, orient the car's forward direction along `+X`, scale uniformly so the shape fits a bounding sphere of radius 1.
6. **Pair for morphing.** Sort both shapes' points in Morton (Z-order) order and pair them index by index, so nearby points in one shape morph to nearby points in the other. Then apply **one shared random permutation to both arrays**. This keeps the pairing and makes any prefix of the array an unbiased random subset of the shape (needed for mobile and for adaptive point counts).
7. **Quantize and write.** `Int16` x, y, z. Each shape has its own `scale` (the car and quadruped use `1.0`, because they fit a radius-1 sphere; the rings use `3.0`, because the outer ring has radius 3). A coordinate is stored as `round(value / scale * 32767)`. Little-endian, interleaved.

### 2.4 Output format

`public/models/scene-points.bin`: shape A (car) points, then shape B (quadruped) points, then the ring points. `Int16` triples.

`public/models/scene-points.json`:
```json
{
  "version": 1,
  "count": 30000,
  "quant": 32767,
  "shapes": [
    { "name": "car",  "offsetBytes": 0,      "points": 30000, "scale": 1.0 },
    { "name": "quad", "offsetBytes": 180000, "points": 30000, "scale": 1.0 },
    { "name": "rings","offsetBytes": 360000, "points": 1200,  "scale": 3.0 }
  ],
  "sourceHash": "sha256 of the script inputs (names only, not the model)",
  "generated": "ISO date"
}
```
Budgets: each shape at most 200 KB; total `.bin` at most 450 KB uncompressed and at most 350 KB with brotli. If the host serves `.bin` uncompressed, say so in the plan.

### 2.5 Quadruped (`scripts/make_quadruped.py`)

Generated by area-weighted sampling of primitives, in the same normalized space, forward `+X`, ground `y = 0`, then normalized to a bounding sphere of radius 1 like the car. Starting dimensions (before normalization; tune until it reads clearly as a four-legged robot from the three-quarter view):

| Part | Primitive | Size and placement |
|---|---|---|
| Body | Box | 1.00 long, 0.22 high, 0.38 wide, center at `y = 0.62` |
| Head or sensor pod | Box | 0.18 long, 0.14 high, 0.30 wide, at the front top (`x = +0.55`, `y = 0.72`) |
| Upper legs (4) | Cylinder, radius 0.035 | Hip at `x = +/-0.38`, `z = +/-0.22`, `y = 0.58`; length 0.34, angled forward on front legs and backward on hind legs |
| Lower legs (4) | Cylinder, radius 0.028 | Knee to foot, length 0.34, angled opposite the upper leg |
| Feet (4) | Sphere, radius 0.04 | At the ends of the lower legs, near `y = 0.04` |

It is a generic quadruped. Do not copy any real product's distinctive industrial design details. No logos or text.

### 2.6 Range rings

About 1,200 points on five concentric rings in the ground plane (radii 0.6, 1.2, 1.8, 2.4, 3.0 in scene units), evenly spaced around each ring, plus a few radial ticks. Colored with `--concrete`-like grey; they do not morph.

### 2.7 Determinism and tests

- Fixed seeds; running the scripts twice produces byte-identical output (test compares SHA-256).
- Unit tests assert: point counts match the manifest; all coordinates in `[-32767, 32767]`; the first 12,000 points of each shape have a bounding box within 5% of the full shape's; file sizes within budget.

## 3. Rendering approach

**Default: raw WebGL2, no library.** The scene is one point draw plus one small ring draw. That is about 200 lines of code, so three.js would add roughly 100 KB or more of gzip for a single use of `Points` and `ShaderMaterial`. The Stage 4 plan must either use raw WebGL2 or justify in one paragraph why a library is worth its weight (and then tree-shake it, with a bundle budget in section 7).

Context settings: `antialias: false`, `alpha: false` (opaque canvas; clear color is `--viewport`), `depth: true`, `powerPreference: "high-performance"`, `premultipliedAlpha: false`.

Draw calls: at most two (points, rings). No shadows, no post-processing, no blending, no sorting.

### 3.1 Vertex data

Per vertex: `aCar` (vec3 from Int16, normalized), `aQuad` (vec3). The scatter position and the random seed are computed in the shader from `gl_VertexID` with a hash function, so no extra buffers are needed.

### 3.2 Vertex shader responsibilities

- `getPos(state)`: returns scatter, car, or quad position for a point.
- `pFrom = getPos(uFrom)`, `pTo = getPos(uTo)`, `seed = hash(gl_VertexID)`.
- **Stagger:** `t = smoothstep(0.0, 1.0, clamp((uT - seed * 0.35) / 0.65, 0.0, 1.0))`.
- `pos = mix(pFrom, pTo, t) + flow(seed, uT)`, where `flow` adds a small sine-based displacement that peaks at `t = 0.5` and is zero at both ends, so shapes dissolve organically and then settle exactly.
- Idle scatter drift: `scatter.xz` rotates slowly with `uTime`; `scatter.y` bobs by under 0.02.
- **Sweep:** `azimuth = atan(pos.z, pos.x)`; `trail = mod(uSweep - azimuth, 2π) / 2π`; `flash = exp(-trail * 6.0)`.
- **Height color:** `h = clamp(pos.y / uHeightMax, 0, 1)`; color is a two-segment mix `ground to mid to top` from the ramp tokens.
- `gl_PointSize = baseSize * (1.0 + flash * 0.6) * perspectiveScale`, clamped to the device's `ALIASED_POINT_SIZE_RANGE`.
- Ambient dimming: `color = mix(color, uBg, uDim)` (instead of alpha), so there is no blending.

### 3.3 Fragment shader

- Round points: discard fragments outside a circle in `gl_PointCoord`, with a 1-pixel soft edge.
- `color = mix(color, uFlashColor, flash * 0.85)` where `uFlashColor` is the fog color.

### 3.4 Uniforms

`uFrom`, `uTo` (int state ids), `uT` (0 to 1), `uSweep` (radians), `uTime`, `uHeightMax`, `uDim`, `uBg`, `uFlashColor`, `uRampGround`, `uRampMid`, `uRampTop`, `uPointScale`, `uMVP`. All colors come from the CSS custom properties, read once at init and again on theme change.

### 3.5 Camera

- Perspective, field of view 35 degrees, looking at the shape's center.
- Base view: yaw 28 degrees, pitch 14 degrees (a three-quarter view).
- Idle: yaw oscillates by plus or minus 3 degrees with a period of 18 seconds.
- Pointer parallax (only on `(hover: hover) and (pointer: fine)`): up to plus or minus 4 degrees of yaw and 2 degrees of pitch, damped.
- No user-controlled orbit, no zoom, no drag. The scene never captures wheel or touch events, so page scrolling is never blocked.

## 4. Scene states and scroll choreography

### 4.1 States

| Id | State | Dim | Notes |
|---|---|---|---|
| 0 | Scatter | 0.45 | Ambient, slow drift |
| 1 | Car | 0 | Rings visible |
| 2 | Quadruped | 0 | Rings visible |

### 4.2 Intro (once)

- Plays on the first visit in a session (flag in `sessionStorage`); later loads start already resolved to the car.
- 2,400 ms: scatter to car with per-point stagger, easing `cubic-bezier(0.22, 1, 0.36, 1)`. The sweep spins 1.5 turns, decelerating to its idle speed (0.15 turns per second).
- The text content is not delayed or animated by the intro.

### 4.3 Desktop scroll mapping (1024 px and up)

Anchors are measured from the DOM (the vertical center of each element), not hard-coded.

| Scroll range | From to to | Hold |
|---|---|---|
| Top of page to hero end | Car (resolved) | Hold car |
| Hero end to the Spot row's center | Car to quadruped | Transition in the middle 50% of the range |
| Spot row center to the WayFinder row center | Quadruped to car | Middle 50% |
| WayFinder row center to the Baton row center | Car to scatter | Middle 50% |
| Baton row center to the page end | Scatter | Hold |

Each transition's `uT` is the scroll fraction within the middle half of its range, passed through a smoothstep. The first and last quarters of each range hold the shape still, so the reader sees a clear form while reading a row.

### 4.4 Hover and focus override (desktop)

When a project row has pointer hover or keyboard focus, the scene eases toward that row's state over 600 ms; on release it eases back to the scroll-determined state. Hover never fights scroll: scroll sets the base; hover applies a temporary override that is cleared on `pointerleave` or `blur`.

### 4.5 Mobile and tablet (below 1024 px)

- One inline viewport in the hero. Intro plays once (same rules). Idle sweep and drift only.
- Point count 12,000 (prefix of the array).
- No scroll-linked states. Project rows may show static posters (see `04`).
- Device pixel ratio capped at 1.5.

## 5. Motion tokens and rules

| Token | Value |
|---|---|
| Intro duration | 2,400 ms |
| Poster to canvas crossfade | 200 ms, once |
| Hover override ease | 600 ms |
| Morph easing | `cubic-bezier(0.22, 1, 0.36, 1)` |
| Sweep (idle) | 0.15 turns per second, linear |
| Sweep (intro) | 1.5 turns over 2,400 ms, decelerating |
| UI interaction (links, buttons) | 0 to 120 ms or instant |

- **Photosensitivity:** the sweep makes a small region brighten at most once per revolution. Idle period is about 6.7 s; the fastest moment (intro) gives about 0.6 flashes per second at any point, and never full-screen. This stays well under the 3-flashes-per-second limit in WCAG 2.3.1. Do not increase flash area or speed without re-checking.
- Nothing else on the page animates. No entrance animations, no parallax on text, no cursor effects.
- Only the scene and the lane line are scroll-driven.

## 6. Fallbacks and the exact conditions for running the scene

The scene runs only if all are true:

1. `canvas.getContext("webgl2")` succeeds.
2. `prefers-reduced-motion` is not `reduce`.
3. `navigator.connection.saveData` is not true and the effective connection type is not `slow-2g` or `2g` (when the API exists).
4. The scene module loaded and initialized without throwing.
5. The viewport element is in the document and has non-zero size.

Otherwise: the poster stays (or returns), the point file is never requested if conditions 1 to 3 fail before load, and no error appears for the visitor. Errors are caught and logged to the console with a single `scene:` prefix in development only.

**Context loss:** on `webglcontextlost` call `preventDefault()`, show the poster, and attempt to restore on `webglcontextrestored`.

**No-JS:** the poster is real `<img>` markup in the HTML, not injected by script.

### 6.1 Poster generation (`scripts/render_poster.py`)

Renders the same point data with the same camera, ramp colors, and ring points onto a `--viewport` background, so the poster matches the live scene. Outputs:
- `poster-car` and `poster-quad` and `poster-scatter` at 1600 by 1200 (desktop) and 800 by 600 (mobile), as AVIF with WebP fallback, with explicit `width` and `height` on the `<img>`.
- Viewport sizing these must fill: on desktop the panel is 4:3, the full width of grid columns 7 to 12 (at most 536 by 402 CSS px; see `03` section 4.4), so the 1600 by 1200 poster fits without cropping and covers the largest panel at about 3x density. On tablet (50svh) and mobile (about 46svh) the panel isn't 4:3, so the poster is drawn with `object-fit: cover`, centered on the subject. The canvas uses the same box.
- `og-home.png` at 1200 by 630: the car poster with the name `Jacob Webster` and the line `Perception and autonomy software` set in Overpass 700. This is the only place text is baked into an image; the alt text and meta tags carry the same words.
- Deterministic, so re-running changes no bytes.

## 7. Performance budgets

| Item | Budget |
|---|---|
| Points drawn | 30,000 desktop; 12,000 mobile; never more |
| Draw calls | 2 |
| Per-frame JavaScript allocations | 0 (reuse typed arrays and matrices) |
| Frame time target | 16.6 ms; median at most 12 ms on a mid laptop |
| Scene JS (raw WebGL2) | at most 25 KB gzip |
| Scene JS (if a library is justified) | at most 180 KB gzip, tree-shaken |
| Scene data | at most 450 KB uncompressed, at most 350 KB brotli |
| Scene work at load | none until idle; the scene never blocks LCP, TBT, or INP |

**Adaptive quality:** after the intro, sample frame time for 90 frames. If the median is above 22 ms, reduce the drawn count to 16,000, re-sample, then to 8,000 if still above. Counting works by changing the `drawArrays` count, which is why the arrays are shuffled prefixes. If `navigator.hardwareConcurrency <= 2` or `deviceMemory <= 2`, start at 12,000. The live count shown under the viewport always shows the current count.

**Lifecycle:**
- Pause the render loop when the tab is hidden (`visibilitychange`) and when the viewport is offscreen (`IntersectionObserver`). On resume, do not re-play the intro.
- Resize with a `ResizeObserver`; set the canvas to CSS size times `min(devicePixelRatio, cap)`; avoid layout thrashing.
- Idle loop uses `requestAnimationFrame` only; no timers that duplicate frames.

## 8. What the scene must never do

- Capture wheel, touch, or key events, or trap focus.
- Render text.
- Show numbers that aren't real.
- Load anything from a third-party host.
- Block rendering of text, links, or buttons.
- Ship raw model files or textures.
- Imply that the point cloud is real sensor data.
- Reproduce any company's logo or trade dress.

## 9. Tests and checks (run in Stage 3 and 4; paste output)

**Asset checks (`check:assets`)**
- `git ls-files | grep -i assets-private` returns nothing.
- `git log --all --name-only -- assets-private` returns nothing.
- No file with extension `.obj .fbx .gltf .glb .usdz .blend .mtl` exists anywhere under the build output.
- No file in the build output has a SHA-256 equal to any file in `assets-private/`.
- Texture-like images (4096-pixel PNGs from the purchased set) are absent from the build output.
- `.bin` size within budget.

**Scene checks (Playwright)**
1. Default desktop load: after idle, a `canvas` exists in the viewport; the poster is hidden; the live count equals the manifest's count (or the reduced count).
2. `getContext` stubbed to return `null`: poster visible; no console errors; no request for `scene-points.bin`.
3. `reducedMotion: "reduce"`: no canvas; poster visible; no lane-line fill.
4. `saveData` simulated: no request for the scene module or the point file.
5. JS disabled: poster `<img>` present; content intact.
6. Scroll to each project row's center; capture screenshots; confirm the silhouette is the expected state (visual review plus a coarse color histogram sanity check).
7. Throttle the CPU 4x (CDP) and record frame times over 5 seconds; report median and p95. If the median exceeds 22 ms, adaptive quality must have stepped down; confirm the count readout dropped.
8. Resize 1280 to 375 and back; no errors; canvas resizes; no scroll jump.
9. Switch the color scheme; the scene's background and ramp colors update.

**Determinism**
- Run the sampling scripts twice; SHA-256 of both outputs match.
